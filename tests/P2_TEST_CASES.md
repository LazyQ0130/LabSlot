## 2. P2 功能与规则

- 学生已登录且真实学生账户仍存在时，才可创建/取消/查询本人预约；业务层独立检查 `AuthSession`，不是仅靠 UI 菜单限制。
- 创建窗口为本地今天到第六天，共 7 个自然日；公历日期按年月天数和闰年检查。时段 0～8 对应 08:00～17:00 的九个一小时区间，开始时间必须严格晚于当前时刻。
- 同电脑在不同日期/时段可以预约；同日期时段座位占用或学生已有其他座位则拒绝。故障电脑禁止创建，视图中 `!` 优先于 `#`。
- 确认前完整预检；确认后重新加载学生/电脑/预约并验证，写入边界重查开始时间。成功持久化后才发布编号/成功信息。
- 编号取全部现存记录的最大值加一，包括已取消记录；原数据乱序也正确，INT_MAX 后停止创建，不溢出回绕。
- 默认查询本人所有有效记录，含过去未取消记录；可以查看全部历史与取消记录，按日期、时段、编号排序。查询不改原文件字节或修改时间。
- 只取消本人有效且未开始的记录，确认后改为 `BOOKING_CANCELLED`，不删除；远期旧预约即使超过今天的创建窗口，只要尚未开始也能取消。
- 主菜单/管理员基础座位入口保持 P0 输入兼容；学生指定视图每次重读，数量仅解释座位符号，不冒称实际上机人数或统计报表。
- 不修改学生累计小时数，不写 `error.txt` 或 `count.txt`，未开发 P3/P4 功能。

## 3. 文件、内存和错误边界

文件：`data/reservations.txt`，UTF-8 无 BOM，六字段：

```text
预约编号|学号|电脑编号|YYYYMMDD|slot_index|状态
```

支持 LF/CRLF、乱序记录、末行无换行；拒绝错误字段数、空字段、非法标识、非八位日期、不存在的公历日期、编号/电脑/时段/状态越界、整数溢出、NUL、BOM、超长行、重复编号和两类活跃预约冲突。允许历史记录保留；历史学号做格式校验，当前操作人的真实账户则重新核验。

加载与保存前均进行完整校验。零字节为合法空表，运行中缺失/损坏文件是错误，绝不初始化覆盖。保存复用现有 `storage.c` 独占 `.tmp`、刷新、关闭、同目录替换；失败保留原目标，可能保留临时文件供检查。

`ReservationList` 零初始化、堆上按需扩容，从 64 条至最多 100000。`realloc` 失败不丢原指针；容量和字节乘法均检查上限。读取结果只有完整成功才替换调用方集合；失败保持旧输出；释放后清零。排序指针索引检查全量编号/冲突，避免两两遍历，不改变原记录顺序。

`BookingResult` 成功值为 `BOOKING_OK == 0`；新预约存储 API 的成功值为 `STORAGE_OK == 0`。现有 P0/P1 布尔存储接口不改签名，调用方不得混淆。学生账户加载内部的内存/读取失败均不会误报为“学生不存在”；预约自身分配失败细分为 `BOOKING_NO_MEMORY`。

## 6. 测试实现与已修正问题

- 生产代码只通过 `BookingContext` 获取时间；测试 API 和固定 UI 驱动显式注入 `TestClock`。测试使用的固定日期、`LAB_TEST_*` 环境读取均在 `tests/` 中，不作为正式程序后门。
- 动态分配故障使用 GCC 链接器 `--wrap=malloc/calloc/realloc`，逐个真实分配点失败，并直接检查旧指针、输出与磁盘快照。
- Windows MinGW 的内联/导入别名使最初的标准 I/O 链接包装未命中；测试当时得到 141/147，6 个模拟 I/O 失败用例实际未注入故障。改为**仅测试构建**预包含 `io_faults.h` 的标准 I/O 替身，写/刷新/关闭错误均真实到达保存代码；正式源码与正式编译不启用替身。修正后完整验证通过，未降低“失败不提交”的断言。
- 首次测试驱动曾保留 stdout 的 CRLF 尾部 CR，将数字结果误判成字符串，已修正驱动解析；不把该轮作为通过记录。
- 保存流程除确认前/正式调用开始检查外，在写入边界再检查时间，推进时钟用例精确验证开始时刻到达后拒绝，不以冲突等别的失败替代此断言。

## 9. 已知限制与 P3 复用

未发现未解决的 P2 验收失败。Linux/macOS、不同 MinGW C 运行库、实际磁盘耗尽、断电和多进程并发未验证；本阶段明确使用单进程快照，不承诺跨文件事务或断电耐久。Windows 真锁验证是实际系统故障；ENOSPC/刷新/关闭错误是可控注入，不冒称实际填满磁盘。账户仍沿用 P1 教学明文密码限制。

P3 可复用 `Reservation`/`ReservationList`、完整加载/验证/保存与释放接口、`booking_get_seats`、`booking_check_time`、`auth_session_has_role`。管理员确认故障时的受影响未来预约处理与权限流程尚需 P3 单独实现，不能把管理员伪装成学生调用 `booking_cancel`。

按当前仓库的用户约定，验收后以 `feat: implement P2 laboratory reservations` 提交，并正常推送至 `origin/main`；不提交运行数据、二进制或测试临时目录。
