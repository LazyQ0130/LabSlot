## 数据结构与业务约束

- `FaultReport` 沿用已有字段；`FaultReportList` 为自有堆数组，零初始化、按需扩容、最终 `storage_free_reports`，最多10000条，不可浅复制后各自释放。
- `error.txt`：UTF-8 无 BOM，`id|student_id|computer_no|YYYYMMDD|detail|status`，待处理0/已处理1。支持 LF/CRLF、末行无换行。全部字段、日期、状态、UTF-8、编号唯一和同学生同电脑待处理唯一都完整校验；排序指针索引避免二次方查重。失败不发布部分读取结果，保存前再次全量验证。
- 说明1～255字节，拒绝截断、非法 UTF-8、BOM、NUL、控制字符、分隔符、首尾ASCII空格；中文按实际UTF-8字节计。编号为全部历史最大值+1，INT_MAX耗尽时明确拒绝，已处理编号不复用。
- 学生身份只来自当前会话，重新读取对应角色账户；不能传入别人的学号作为报告人。上报不改电脑/预约；已有本人同机待处理报告或电脑已故障均拒绝新建，历史仍可查看。
- 管理员维护和查询在业务层检查角色及真实账户；`admin_query_*` 是专属只读接口，没有伪造学生会话调用 `booking_query`。
- `AdminUsage`/`AdminStudentInfo` 仅投影基本身份和预约事实，不包含密码或 `Student.time`。有效预约包括过去未取消记录；历史总数包含有效与取消。缺失账户引用、损坏/读取失败明确报错，不当作零预约。人数只称预约人数，不冒称实际到场。

## 预约联动与一致性

标故障前完整读取电脑/预约，显示影响记录的编号、日期、时段、学号，确认后重新验证。在最终确认时刻严格未开始的该机有效预约改为取消；开始时刻相等已开始，保留历史。所有取消记录保留，预约编号不复用。故障符号 `!` 优先，新预约重读电脑状态后拒绝；恢复正常不复活已取消记录。公共和管理员基础座位图重新读文件，避免显示启动缓存。

`storage_apply_maintenance()` 为单次操作发布意图：

```text
P3|1|action|computer_no|report_id|YYYYMMDD|hour|minute|second
```

1. 预读/校验相关完整来源与临时路径。动作1标故障、2恢复、3仅关闭报告；报告编号0表示独立维护。确认时刻写入日志。
2. 独占生成 `maintenance.txt.tmp`，刷新/关闭后替换到 `maintenance.txt`，意图发布前不改任何目标。
3. 按电脑 → 预约 → 报告顺序完成目标快照。报告状态最后保存，不能先声称已处理而关联更新失败。
4. 全部一致后将未完成日志移动到 `maintenance.done.txt`，保留上一条完成意图供诊断；归档失败同样保留待恢复状态。
5. 启动在补建数据文件之前恢复。按日志固定时刻重放，停机期间开始的预约仍按原确认时刻处理；只保存尚未达到的目标状态，重复恢复无重复取消/编号变化。
6. 恢复时逐个将本操作遗留 `.tmp` 移动到明确的 `.recovery.txt` 备份，再生成新快照；不删除或批量清理文件。意图发布前的遗留临时文件不自动归档，拒绝覆盖。
7. 未完成意图存在时，全部公开保存接口、预约、故障及管理员一致视图查询都被门禁阻止；恢复失败保留证据，启动非零退出。低层只读加载保留给恢复/诊断调用。

独立电脑维护、确认故障、恢复后关闭、仅关闭报告复用同一协调器。Windows 同目录替换仅对共享/锁冲突和访问拒绝做最多5次短暂尝试，合计等待100毫秒；持续失败仍保留快照和意图并返回错误。测试中出现一次短暂 Windows 错误5导致未到预定注入点，增加此有界重试后完整验收通过；真实持续文件锁仍失败并可恢复。

保证正常成功后一致、普通写失败不报成功、两个保存之间真实进程退出后重启可继续完成、无法恢复时阻止相关写入。**不提供数据库跨文件原子事务、并发写入协调或物理断电耐久保证。** 单进程使用，日志和目标文件需一起备份，外部任意篡改/混合恢复不同版本不在自动恢复保证内。

## 测试覆盖与真实注入

P3 顶层119用例及分配失败子循环覆盖：

- 成功上报/文件格式/中文/255字节边界、唯一编号、跨进程恢复、重复待处理拒绝、已处理同机历史、INT_MAX、10000/10001容量；超长、空、分隔符、控制符、无效UTF-8/NUL、损坏日期/状态/字段、重复编号与重复待处理键。

- 标故障/恢复/重复操作、禁止新预约、故障优先、过去/已开始/相等开始边界保留、未来取消、确认时刻推进复查、恢复后新预约编号不复用。
- 三种报告处理、状态与电脑分离、待处理/已处理/电脑过滤、重复处理、关联操作失败后恢复，报告最后关闭。
- 真实姓名/学号/电脑、精确学号、有效/全部历史、空记录、孤立账户引用、损坏文件不显示零预约、不泄露密码、不改变累计时间。
- 测试编译以 `-include tests/io_faults.h` 重定向 stdio，分别在日志/电脑/预约/报告快照的真实 `fprintf`/`fflush`/`fclose` 注入失败；正式代码无环境变量后门。上报单文件也执行写/刷新/关闭失败，旧报告保留。
- 测试驱动在第2/3/4快照开始写时真正 `_Exit(86)`，形成意图已发布、电脑已替换而预约未保存、预约已保存而报告未保存三种现场；随后运行正式 `smart-lab.exe` 验证启动恢复。没有用预制成功输出代替进程中断。
- Windows `CreateFileW` 实际锁住电脑/预约/报告/完成日志禁止替换，以及禁止报告读取；验证失败、日志保留、锁解除后重试恢复。来源缺失/损坏、日志损坏、目录占据临时路径、恢复幂等（内容及修改时间不变）也有测试。
- 链接器逐次包装 malloc/calloc/realloc，覆盖提交、加载、预览、报告处理及管理员查询所有实际动态分配位置，验证失败输出/释放与发布意图后的继续恢复。
- 固定时钟 UI 完整学生上报、维护/报告过滤/处理、两种管理员查询、公共座位刷新、非数字/超长/EOF/放弃、P4占位。每个进程检查合成密码未泄露，保护账户/统计文件；最终比较真实开发目录所有文件字节。

## 已知限制与未验证边界

教学明文密码沿用原模型，不是生产安全方案；没有密码哈希/加密、限速、管理员审批，任意控制台使用者仍能按课程要求注册管理员。临时账户快照也应作为敏感数据保护。测试/日志不打印凭据。

本轮实测 Windows GCC 16.2.0；Linux/macOS、其他编译器/MinGW发行版、实际磁盘耗尽、系统物理断电未验证。I/O错误是可控真实调用注入，进程退出是真实 `_Exit`，不等同于硬件掉电。系统时钟回拨/时区变化按每次最终确认的本地墙钟解释。当前故障状态与过去有效预约可能重叠，预约人数与座位符号数量采用各自定义，界面不会冒称签到。
