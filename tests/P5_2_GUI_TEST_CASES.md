## 页面和交互

学生导航为工作台、座位预约、我的预约、故障报告、个人统计、退出登录，全部可操作；管理员没有新增学生入口，伪造导航也拒绝。原浅灰背景、白卡片、蓝色主色、微软雅黑 UI 字体和焦点/悬停/禁用样式继续沿用，取消预约使用红色强调。

**我的预约**：原生单选虚拟 ListView，六列为编号、日期、时段、电脑、状态、操作；可筛选有效、全部历史和可取消记录，刷新、选择后查看详情/双击详情、取消。页面分别显示有效结果数量、友好空提示或明确读取错误，不把损坏文件当作空表；只接收 booking_query 返回的本人记录。

选择记录后，状态与当前查询时刻只用于显示“可取消”及按钮启用提示。点击取消仍调用 booking_check_cancel 重新确认本人、状态和时刻，展示详情并默认选择“否”；确认后调用 booking_cancel 再次检查。如果确认期间已开始或记录已被取消，显示实际业务错误。取消成功重新查询当前筛选、更新本人统计并使旧座位投影失效，下次进入座位页重新查询。若保存成功而后续查询失败，界面区分已保存与刷新错误，避免将后续查询失败等同于取消未保存。

**故障报告**：上方是 40 台真实电脑状态的下拉框及故障描述输入，用户不能填写报告学号；下方是编号、日期、电脑、状态、描述的本人报告表格。支持全部/待处理/已处理筛选、刷新和完整详情。描述使用 Unicode 原生输入并严格转 UTF-8，拒绝空值、非法字段、截断和超出 255 字节；确认框展示电脑和描述，默认“否”。成功才清空描述，返回全部报告筛选并查询本人列表；失败保留描述。重复未处理报告、故障电脑、账户/文件/恢复错误保留业务中文结果。

**个人统计**：学号、姓名、完成预约小时、有效数、完成数、尚未完成数和取消数全部来自 stats_query_student。显示查询时刻与“已结束的有效预约，不代表实际上机签到”说明；不读 Student.time 作为权威值。刷新失败不展示旧数值。工作台继续使用同一统计 API，并新增预约管理/报障快捷入口与刷新按钮。

## API、所有权和生命周期

| 功能 | 实际既有 API |
|---|---|
| 三种预约筛选 | booking_query、BOOKING_QUERY_ACTIVE/ALL/CANCELLABLE |
| 取消 | booking_check_cancel、booking_cancel |
| 真实电脑状态 | fault_read_computers |
| 本人报告、提交 | fault_query_reports、fault_require_role、fault_submit |
| 个人统计/工作台 | stats_query_student |
| 会话 | auth_session_has_role、auth_logout，业务层重查真实账户 |
| 内存/字段/时刻 | storage_free_reservations/reports、utils_valid_field、utils_local_time/slot_future |

GUI 不直接读写任何业务 TXT，不重写预约/故障/统计规则。预约与报告集合由 GuiApp 独占，不浅复制后分别释放。刷新先撤销旧表格行与选择，再释放旧集合并重新查询；失败不保留旧投影。页面销毁时先禁止通知访问旧页面，再销毁 ListView/子控件、释放集合、清空指针。注销和 WM_DESTROY 同样走清理路径。

ListView 使用 LVS_OWNERDATA，只由 LVN_GETDISPINFOW 按需格式化缓存中的列文本，支持 99999 条本人历史而不向控件逐行复制业务记录。通知、WM_PAINT、布局和 DPI 更新均不读取业务文件；查询仅在进入、刷新、筛选和明确业务完成后执行。DPI 更新重建字体并根据实际表格客户区重新分配列宽。

确认/详情框期间 busy 阻止重入和导航；创建/销毁控件时 changing_page 忽略旧选择通知。业务失败仍清理动态内存。同步文件操作可能短暂阻塞窗口，未引入后台线程。

- 所有测试在新建 tests/runs/p5-2-* 下执行；逐场景保护未授权修改文件的哈希及修改时间，检查允许的取消/报告保存结果，最后保护真实开发 data 的内容哈希及修改时间。

## 限制和 P5.3 建议

仍沿用单进程教学文本存储，GUI 单实例不协调控制台或外部编辑器；不要并发写相同 data。不存在后台订阅，页面是上次进入/刷新时的快照，最终取消/提交仍由业务重新验证。取消按钮的显示提示可能随时钟前进过时，实际点击/确认后会拒绝不合法操作。描述沿用单行字段规则，不允许换行；长表格可滚动，完整描述通过详情查看。

本阶段没有学生修改账户、管理员维护/报告处理、学生查询或报表 GUI。下一阶段建议 P5.3 复用原管理员授权、维护恢复日志和统计 API 接入这些功能，并补做真实系统 DPI、多显示器及输入法人工验收；不提前改写这些业务或数据格式。
