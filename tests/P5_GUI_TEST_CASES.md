# P5.1 Win32 图形界面验收

## 范围与开发前检查

基于 `d72b264` 增量实现独立 Win32 GUI。只接入图形基础框架、两角色注册登录/退出、工作台、日期/时段与真实座位查询，以及复用既有 API 的确认预约。不开展后续 GUI 阶段。

开发前阅读 README、model/auth/booking/storage/ui/utils 头文件，auth/booking/ui/main 源码、Makefile、build.ps1、P4 验收记录；同时检查 stats/fault/admin 的业务边界。核对项目原题 PDF 三页的已有渲染预览及架构设计文档。项目中没有独立的老师要求文件；PDF 第三页包含美观、注释、分层等程序设计要求，不另行编造外部要求。

修改前严格构建并运行五套测试，基线 **577/577**：P0 57、P1 134、P2 155、P3 119、P4 112。见 [基线日志](results/p5-baseline.log)。

## 设计与架构

浅灰背景、白色圆角卡片、蓝色主按钮/选中状态，微软雅黑 UI 系统字体。原生 Unicode EDIT、日期选择器、下拉框及 owner-draw BUTTON；5 排 × 8 列座位为视觉中心，颜色与中文状态同时表达含义。父窗口使用 GDI 双缓冲，子控件保留原生输入、焦点、Tab 与密码样式。输入焦点有蓝色边框，按钮/空闲座位具有悬停及键盘焦点效果。

默认客户区 1280×800 逻辑像素，根据实际窗口 DPI 和显示器工作区限制初始尺寸；最小客户区约 1000×650，支持最大化、拖动缩放及 WM_DPICHANGED。逻辑尺寸统一转换为物理像素，字体随 DPI 重建。空间不足时省略工作台辅助统计卡，仍保留主要入口。主框架固定 224 逻辑像素导航栏，学生与管理员有不同的预约/概览名称及后续模块说明。

`GuiApp` 持有窗口资源、AuthSession 和只读展示投影；页面重建逐个销毁控件并清空密码，退出/销毁清除会话。绘制中创建的画刷、画笔、位图/DC 用后立即释放；字体/页面画刷按窗口生命周期释放。没有 GDI+、C++ 或第三方 GUI 运行库。

## 真实 API 和错误处理

| 操作 | 既有 API |
|---|---|
| 启动 | storage_recover_maintenance、storage_initialize |
| 注册/登录 | auth_register_admin/student、auth_login_admin/student |
| 会话/退出 | AuthSession、auth_session_has_role、auth_logout |
| 座位查询 | booking_get_seats |
| 确认前后预约 | booking_check_create、booking_create |
| 工作台本人统计 | stats_query_student |
| 恢复门禁/字段/时间 | storage_writes_allowed、utils_valid_id/field、utils_clear_secret、utils 本地时钟工具 |

GUI 不解析或写业务 TXT，不重新实现密码验证、冲突检查和统计聚合。注册按角色使用真正的 auth API，成功后返回登录。管理员没有预约按钮，即使伪造控件命令也无法选座或创建预约；booking 业务层继续拒绝管理员会话。

宽字符接口通过带 WC_ERR_INVALID_CHARS / MB_ERR_INVALID_CHARS 的严格 UTF-8 转换，不强转指针、不截断后提交；对 UTF-8 字节容量、空值和业务合法性复查。原生输入限制比字段上限多留一个字符，以便将超限明确拒绝。密码控件使用 ES_PASSWORD，提交后清空控件和临时缓冲，不输出输入原文。

业务结果使用原有枚举对应中文消息，分别保留密码错误、账户不存在、重复账户、文件错误、内存/容量、时间过期、窗口超限、学生冲突、座位占用和故障等信息。恢复门禁单独明确说明。底层已有存储错误枚举合并读取/格式/保存失败，GUI 同样如实说明这个范围，不推断某个具体文件原因。查询失败时 40 个座位变为“未知”并禁用，不继续显示旧投影或伪造零占用。

确认框默认“否”。预检通过才显示学号、日期、时段及电脑号；确认后 booking_create 重新检查账户、时钟、文件、冲突和故障，保存成功才显示编号，再查询座位。取消确认不写数据；确认期间出现冲突也拒绝。单窗口同步操作期间以 busy 标志防止重入，不输出虚假成功。

## GUI 功能测试方法与证据边界

测试驱动链接真实 GUI 模块和 Win32 控件，通过 WM_COMMAND/WM_NOTIFY、控件值和 AuthSession 验证实际页面行为，不将业务 API 单测当作整个 GUI 验收。测试自己的线程只应答本测试进程所属确认对话框，生产程序没有自动确认/演示账户或测试时钟。测试在新建且忽略的 tests/runs 目录执行；对开发 data 文件内容哈希和修改时间作前后保护断言，最终只归档不含凭据的文本。

覆盖：真实窗口建立及中文 UTF-8 往返、非法代理项/非法 UTF-8/字节超长拒绝、密码控件、Tab 顺序、Enter 登录、学生/管理员注册登录、重复注册、错密码、确认密码不一致、成功注册返回登录、错误后保留 ID/清空密码、退出清空会话、不同角色控件及管理员伪造命令拒绝。

座位覆盖：40 个原生按钮与真实数量、日期/时段值、切换清除选择、悬停、空闲可选、故障/已预约不可选、确认放弃无写入、成功保存与刷新、过期拒绝、查询后数据改变导致的冲突、确认对话框期间出现新冲突、重建窗口/重新加载后占用与故障持久恢复。错误夹具覆盖损坏账户、损坏预约、损坏电脑和不可恢复维护日志，均验证原始文件字节不被重置。

资源覆盖：80 次工作台/座位页切换并真实绘制，比较 GDI 和 USER 对象计数无持续增长；销毁后字体、画刷、控件与会话清空。

## DPI、缩放与实际画面

自动化向真实窗口发送 96、120、144 DPI 的 WM_DPICHANGED，逐项检查登录、注册、工作台、座位页，在 1000×650 和 1280×800 两种逻辑尺寸下控件位于客户区内，座位按行对齐，无越界。共 3×2×4=24 个布局场景。它验证窗口缩放路径和布局计算，**没有改变机器的系统显示缩放，也不等同于三种系统 DPI 的人工完整验收**。真实多显示器拖动切换 DPI、系统级 125%/150% 字体渲染和输入法组合输入仍未人工验证。

真实画面来自运行的 Win32 GUI 模块，没有生成示意图。截图所用数据在独立测试目录，由真实业务保存/查询得到；显示的 P5Student 是合成测试账户，未使用真实用户资料。本地保存的工作台和座位图通过独立测试入口运行生产 GUI 页面；另实际启动独立复制的生产 EXE 核对过登录页面。不是替代正式业务的内置假数据。按 AGENTS.md“验收记录仅归档脱敏文本”的约定，截图保存在 docs/screenshots/，不纳入 Git，以下链接用于本地查看。

## 尚未接入、已知问题与下一阶段
