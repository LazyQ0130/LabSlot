## P1 测试方法

```powershell
python tests/test_p1.py --executable smart-lab.exe --cc gcc
# 或 build.ps1 -Test；或 mingw32-make test
```

每个用例设置独立工作目录，所有账户和 `.tmp` 都在 `tests/runs/p1-<运行标识>/` 内。真实开发 `data/` 会在测试前后逐字节比较；不批量删除任何文件，不记录 stdin、密码或账户原文到日志/报告。失败报告只记录异常类别，避免断言展示凭据。单次测试进程超时 10 秒。

API 驱动独立构建，使用与项目相同的 C11 和 `-Werror`。它直接检查每个会话字段，认证失败和退出后会话所有字节归零；确认新学生的外部输入时长被忽略并设为 0；验证存储读取失败不把输出条数改为 0，且不部分发布账户数组。

- `include/model.h`：角色类型和堆上单角色账户集合。

- `include/ui.h`、`src/ui.c`、`src/main.c`：真实角色入口、会话保护的角色菜单及退出流程。
- `Makefile`、`build.ps1`、`.vscode/tasks.json`：P0/P1 构建与测试入口。
- `tests/test_p0.py`：仅适配两处已变化的菜单要求，保留原安全与持久化断言。
- `tests/TEST_CASES.md`：保留 P0 历史记录，补充本轮回归入口。

## 覆盖范围

| 类别 | 断言 |
|---|---|
| 注册 | 双角色多账户、同角色重复拒绝、旧账户保留、新学生时间为 0 |
| 登录 | 正确凭据、错误密码、不存在账户、失败重试、独立进程重启 |
| 角色隔离 | 跨角色账户失败；同名账户分别校验各自密码；退出后切角色须重新认证 |
| 会话 | 角色、标识、标志正确；退出/失败/EOF 清理；空标识、未登录、错角色均不授权 |
| 菜单 | 公共及角色座位展示；全部后续功能统一未开放；无预约、故障或统计输出 |
| 输入 | 空/超长 ID、非法标识、UTF-8 字节边界、超长姓名/密码/确认、不一致、NUL/非法编码、多级非数字、各字段 EOF |
| API 边界 | NULL、未终止字符数组、无效内存快照、重复快照、负时长、无效角色/数量 |
| 文件损坏 | 缺/多字段、空字段、空行、重复、非法 UTF-8、控制符、BOM、长行、负/溢出时长、超容量 |
| 兼容性 | 原有账户格式、CRLF/末行无换行、31/63 字节上限、已有累计时长保留 |
| 容量 | 管理员 30/学生 1000 恰满仍可读取；新增拒绝；超一条报损坏/容量错误 |
| 读失败 | 运行中账户文件缺失；Windows 实际独占锁文件，返回存储错误而非不存在 |
| 写失败 | 遗留临时文件、临时路径为目录、Windows 实际拒绝替换；原目标保留且无虚假成功 |
| 同进程恢复 | 写失败后新账号不能登录，处理明确临时文件后重试成功，无缓存幽灵账号 |
| 数据与日志 | 真实开发数据不变，进程输出及报告无密码 |

## 已知限制

教学明文凭据不是生产安全方案，任何人均可在演示控制台注册管理员。单进程文件快照不保证并发事务或断电耐久。Windows 隔离进程测试验证 UTF-8 数据和菜单，真实交互控制台的密码回显切换尚未人工视觉验证。Linux/macOS、实际磁盘耗尽和掉电未测试。

P1 验收时项目及父目录尚不是 Git 仓库，最初未提交。之后按用户要求初始化 Git，远程设为 `https://github.com/LazyQ0130/LabSlot.git`，使用提交信息 `feat: implement P1 authentication` 提交 P0/P1 源码与脱敏验收记录。运行数据、二进制和测试临时目录不纳入版本控制。
