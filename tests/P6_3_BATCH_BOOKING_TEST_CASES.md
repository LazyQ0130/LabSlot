# P6.3 连续时段预约验收

学生座位页选择“连续1/2/3小时”，蓝色区间标明覆盖起止时间；只有整个区间都可用的电脑可选。点击“连续预约”先显示完整摘要，默认否；确认后业务重新检查并一次保存全部一小时记录。推荐结果携带时长，仍在最终提交时重新验证。个人列表和统计按原有每条一小时规则显示；取消仍逐条执行。

## 原子提交与兼容

`booking_range_mask`、`availability_at` 继续服务推荐与连续预约，不重新实现日期或占用算法。`booking_check_batch` 只预检；`booking_create_batch` 校验真实学生/P3门禁、全部时段、故障状态，**只加载一次完整预约集合**，检查全部冲突、容量和最大历史编号，然后构造1–3条候选记录。提交前重新读取真实账户、设备和系统时刻，并对原始快照前缀复查共同可用性；新记录不与自身冲突。该前缀仅借用内存，唯一所有者在结束时释放整个集合。

完整候选集合只调用一次 `storage_save_reservations`。只有安全替换成功，才发布 `BatchBooking.count` 和全部正式记录/编号；失败保持输出哨兵和原文件。遗留草稿保留，不覆盖、不清理。编号按所有历史记录最大值加一，含取消记录；提前验证 `maximum <= INT_MAX-duration`，不回绕或复用。

文件仍是原六字段Reservation，一条一小时；不增加分组格式或组取消。保留原单条API、P3恢复、控制台双目标。单进程且时钟依赖只读；不承诺外部并发写入、跨进程事务或物理断电耐久。
