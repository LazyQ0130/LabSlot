## 指标口径与公式

每条预约恰占一小时，`BOOKING_ACTIVE` 只表示未取消，不能据此认定预约已经结束或学生已经签到。

| 指标 | 精确定义 |
|---|---|
| 每日有效预约量 | 日期为D且状态为ACTIVE的记录数，未来/进行中也可计入预约量，取消不计 |
| 每日预约小时 | 等于每日有效预约量 |
| 每日学生人数 | 当天有效预约中的不同学号数；学号大小写敏感，同人多时段只计一次 |
| 每日理论容量 | 40台×9时段=360座位小时 |
| 每日预约利用率 | 当天预约小时/360×100% |
| 时段预约率 | 该时段有效预约数/40×100% |
| 周期 | 输入任意合法日期，计算所在周一至周日，不直接加减YYYYMMDD整数 |
| 周有效预约量/小时 | 七天有效预约小时相加，周理论容量2520座位小时 |
| 整周学生人数 | 七天整体按学号去重，不能将每日人数相加 |
| 日均预约小时 | 整周预约小时/7 |
| 整周预约利用率 | 整周预约小时/2520×100% |
| 完成预约小时 | 属于当前学生、状态ACTIVE、时段结束时刻不晚于本次查询时刻的记录数；结束相等计入 |
| 尚未完成 | 当前学生的有效预约总数减已结束有效预约数，包含进行中和未来 |

比例和日均统一显示两位小数。所有人数/小时均为预约事实，不代表真实签到或实际上机。没有故障历史时间轴，因此不使用当前故障数扣减过去日期容量；当前故障电脑上的过去有效预约仍按事实计数。历史学号只需符合预约文件契约，不因该学生后来离开账户表而擦除聚合统计；当前操作者角色与账户存在性仍严格验证。

## 数据结构、权限与性能

- `DailyCount` 放入model作为持久快照投影；只含日期、有效数、去重人数、小时与九时段数量。
- `DailyStats` 包含该聚合、独立的已完成小时、日/时段利用率及本次 `LabTime`。`WeeklyStats` 包含同一来源和时刻的七日报表与整周独立去重。`StudentStats` 仅返回当前学生ID、姓名及本人计数，无他人学号输入参数。
- `StatsResult` 显式区分成功0、参数、权限、账户不存在、存储、内存、容量、时钟、待恢复以及整周越界错误；所有调用比较具体枚举，不混淆旧布尔接口。
- `stats_compute_daily`、`stats_compute_week`、`stats_query_student`、`stats_export_daily` 均在业务层检查对应会话、真实角色账户和 `storage_writes_allowed()`。旧无会话占位声明直接被替换，不保留越权兼容导出入口。
- `Student.time` 保留原账户文件布局与字段校验，是非权威旧缓存。本阶段统计不读取其值计算、不累计写回、不修改学生账户，不新增跨文件同步。
- 日/周从完整校验后的 `ReservationList` 聚合：一次加载、一次扫描，最多选择360/2520个有效记录指针，一次按学号/日期排序同时获得每日与整周人数。不会重复加载七次或按每日人数求整周人数；不把十万条预约放在栈上。
- 存储层原有完整预约校验仍包含必要排序；统计层额外复杂度O(N+M log M)，M最多2520。学生累计为一次扫描。动态内存使用临时指针、安全扩容和明确释放；MAX_RESERVATIONS与周容量的C11静态断言约束int计数上限。
- `utils_slot_ended` 独立判断结束时刻，避免误用P2的“尚未开始”函数。NULL时钟上下文使用本地系统时间，测试通过 `BookingContext` 注入；每次周查询只取一次时刻，七日结果口径一致。
- 支持1000～9999年公历；一周超出支持范围时明确返回DATE_RANGE，拒绝裁剪成不足七天。

## count.txt 存储与失败恢复

编码UTF-8无BOM，实际只有ASCII十进制数字和分隔符。每行13字段：

```text
YYYYMMDD|有效预约数|去重学生人数|预约小时数|slot0|slot1|slot2|slot3|slot4|slot5|slot6|slot7|slot8
```

校验日期有效、严格递增且不重复；总数/小时0～360且相等，九时段每项0～40、总和等于预约总数；学生人数介于最大单时段预约数与总预约数之间，零预约日人数为0。拒绝负号/正号、空白、空行、整数溢出、NUL/BOM、非法字节、多/少字段、非法日期、重复/无序日期、不一致汇总。支持LF/CRLF与末行无换行，保存规范为LF。

`DailyCountList`自有堆集合最多100000个日期快照，含零预约日期；扩容检查乘法和容量边界。满容量仍可更新已有日期，只拒绝新增超限日期。加载部分失败不改变旧输出，保存先验证全部记录。重复日期导出执行替换，不追加重复行；新日期插入有序位置，保留其他日期的聚合字段，CRLF等文本表示在全表保存时规范化。

导出流程：管理员菜单5→2输入日期→展示实时日报→显式确认→重新校验账户/恢复状态并计算预约事实→完整加载并校验旧count.txt→插入/替换所选日→完整校验→独占 `count.txt.tmp`→检查写入/刷新/关闭→复用同目录安全替换→最后才发布成功和输出。

普通启动仅沿用P0创建缺失空文件，不生成统计内容。普通实时查询绝不写count.txt或账户；它不依赖统计快照，即使快照损坏，仍可从有效来源实时计算，但不能覆盖损坏快照。快照是上次显式导出的聚合，学生后续创建/取消或故障取消会使其过时，须重新导出更新；没有自动订阅或隐式修复。

所有快照写入复用P3已有独占临时文件、检查fflush/fclose、Windows有界替换重试/非Windows rename；失败保留旧目标，可能保留失败草稿，不能报告成功。P4不引入跨文件事务，既不自动删除草稿，也不重放/清理P3日志；操作者检查并将明确的失败草稿备份后可重试。未完成维护时四种统计接口都拒绝，快照底层保存也检查门禁。先恢复P3，再从最终预约事实重新计算统计。

- 周内同学生跨七天仅整周计1、每日与整周去重口径独立，日均/2520利用率；跨月/年、2000/2024闰日、2100非闰年、最小/最大支持日期整周越界；完整空周正确。
- 固定时钟2026-10-19的08:59:59/09:00:00/10:00:00/10:30:00/11:00:00/17:00:00及跨日边界。结束相等纳入，进行中/未来/取消不纳入；查询两次重启值相同，INT_MAX旧缓存也不覆盖动态值；不同学生会话只返回本人。
- 一次周查询注入第一次时刻10:15、之后时刻推进到周日17:00，验证七天全部采用首次单一时刻，避免七日报告各自取时。

- 损坏count文件的字段/日期/顺序/重复/聚合/溢出/非法字节均拒绝覆盖；实时查询独立于旧快照。存储保存接口也独立验证坏内存记录。
- 测试构建通过 `-include tests/io_faults.h` 在真实fprintf/fflush/fclose注入失败，或写入前真实 `_Exit(86)`；断言旧count原字节保留、输出哨兵不变。明确备份单个失败临时文件后重试导出成功。

## 已知限制与P5建议

统计只表示预约事实，没有签到或故障历史轨迹，理论容量不会随当前故障数变化。完成小时按本地墙钟查询时刻解释，回拨/时区变化可能改变动态结果；不维护不可回退的累计账本。count只保留每日期最后一次显式导出，无时间戳/审计历史/自动过期订阅；旧快照可能过时，不自动修复其内容。

限单进程，无外部并发修改协调。统计导出只有单文件安全替换，不承诺物理断电硬件耐久；草稿须人工检查并备份后重试。运行数据和P3日志须一起备份，不能混合恢复不同版本。快照日期上限100000，超限新增明确失败。Linux/macOS、其他编译器/MinGW版本、真实磁盘耗尽和物理断电未验证；可控I/O失败与真实进程退出不等同于断电。

账户继续沿用教学明文密码，不是生产安全方案。统计结果/导出/报告不包含密码；不增加密码库、数据库或运行依赖。

P5建议以本次五套自动测试与真实Windows终端流程为验收入口，核对编译/启动路径、UTF-8、EOF、各角色登录退出、预约取消/故障联动、维护中断恢复、日/周/累计公式、快照过时与备份恢复；保留失败现场并整理答辩材料。复用现有授权统计接口、数据投影和安全存储，不在界面层自行计算或将Student.time/count当作实时权威来源。本轮不实现这些P5扩展工作。
