# 智能实验室预约系统 · P3

大学 C 语言课程设计项目。使用纯 C11、控制台菜单和标准 C 文本文件读写，无数据库、网络服务或 GUI 依赖。已完成 P0 基础框架、P1 身份与账户持久化，以及 P2 学生预约、个人查询、取消和按日期/时段显示占用。P3 已完成故障上报、管理员维护/报告处理、预约联动恢复与只读查询；P4 统计尚未实现。

已阅读项目根目录的《智能实验室预约系统.pdf》（3 页）和《智能实验室预约系统_C语言架构设计.md》。按原题保留 40 台电脑、08:00～17:00 共 9 个一小时时段，以及 `error.txt`、`count.txt` 文件名。按本次任务的模型要求，将跨日期/时段的预约拆为独立 `Reservation`，不以电脑上的一个学生姓名表示所有预约。

## 环境与快速启动

- Windows + VS Code + GCC/MinGW-w64；源码遵循 C11。
- GNU make 可选；测试需要 Python 3.9+，只用标准库。
- 程序运行本身不需要 Python，不会联网或安装依赖。
- 文件使用 UTF-8 无 BOM；Windows 实际控制台通过条件编译设置 UTF-8。建议使用 Windows Terminal/VS Code 终端及支持中文的等宽字体。

在 PowerShell 中先进入项目根目录：

```powershell
cd C:\Users\QYF\Desktop\LabSlot
gcc -std=c11 -Wall -Wextra -Wpedantic -Iinclude src/*.c -o smart-lab.exe
.\smart-lab.exe
```

也可以运行构建脚本（自动切换到项目根目录，并把编译警告视为错误）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test
```

本机已将 w64devkit 2.10.0（GCC 16.2.0、MinGW-w64、GNU make）安装在 `%USERPROFILE%\.cache\labslot-toolchain\w64devkit`，并将其 `bin` 追加到用户 PATH。现有终端可能需要重启才能取得新 PATH；`build.ps1` 可以直接找到该缓存路径，也支持 `-Compiler '完整路径\gcc.exe'`。便携工具来自 [w64devkit 官方项目](https://github.com/skeeto/w64devkit/releases/tag/v2.10.0)，没有修改系统 PATH。

Makefile 的用法：

```powershell
mingw32-make
mingw32-make test
# 安装的是 GNU make 时也可使用 make / make test
# 指定工具链：mingw32-make CC='C:/path/to/gcc.exe'
```

VS Code 中用 `Ctrl+Shift+B` 构建；“运行任务”中选择 `LabSlot: Run` 启动，选择 `LabSlot: Build and test P0 + P1 + P2 + P3` 构建并运行四套测试。`build.ps1 -Test` 和 `mingw32-make test` 也会运行 P0、P1、P2、P3 四套测试；可用 `mingw32-make test-p0`、`test-p1`、`test-p2`、`test-p3` 单独运行。

## 当前功能

- 成功编译、链接、启动，主菜单 4 退出（兼容旧的 0）；所有层级 EOF 均正常退出。
- 菜单 1、2 分别进入管理员/学生注册登录入口；3 显示真实加载的 40 台电脑。
- 两种角色均支持多账户、同角色标识查重、密码二次确认、错误后重试和重启登录。
- 每次认证只读取对应角色文件，使用显式 `AuthSession`；角色菜单检查会话权限，退出、认证失败及 EOF 清除会话。
- `Admin`、`Student`、`Lab`、`Reservation`、`FaultReport` 均有字段说明。
- 数据目录/文件缺失时创建；零字节电脑文件初始化为编号 1～40、全部正常。
- 电脑文件已有有效数据时只读恢复，支持乱序记录、LF/CRLF、末行无换行，不重写原文件。
- 5 排 × 8 列，座位为 `01[*]` 格式；每行 47 个 ASCII 显示列，中文只在说明文字中，避免单元格对齐依赖中文宽度。
- 公共主菜单及管理员入口继续显示无日期的基础电脑状态；学生菜单按指定日期/时段重新读取数据，显示 `*` 空闲、`#` 预约、`!` 故障，故障优先。每次切换都重新计算。
- 学生可预约、查询本人有效/全部历史记录、确认取消本人未开始预约；冲突、权限、日期/窗口、学生存在性和文件完整性都在业务层复查。
- 严格拒绝空值、字母、负数、超范围、溢出、尾随文字、NUL 和超长输入；读完并丢弃非法整行，后续输入不受残留影响。
- 学生报告只记录线索，不改电脑/预约；管理员确认故障后才取消该电脑尚未开始的有效预约。
- 管理员可查看/处理报告、恢复电脑、按日期/时段查预约人数，以及精确查询学生信息与预约历史。
- 检查文件打开、读取、写入、刷新、关闭与替换错误，不把失败报告为业务成功；启动或标准流错误返回非零进程码。

## 数据格式与保存策略

| 文件 | 当前行为 | 格式/后续用途 |
|---|---|---|
| `data/admins.txt` | 缺失建空文件；按角色严格读取；注册时保存完整快照 | 每行 `工号\|姓名\|密码` |
| `data/students.txt` | 同上；新学生时长强制为 0，保留已有学生时长 | 每行 `学号\|姓名\|密码\|累计小时数` |
| `data/computers.txt` | 实际解析、校验、初始化或加载 | 每行 `编号\|状态`，正常 0、故障 1 |
| `data/reservations.txt` | 严格加载；确认创建/取消后安全保存，历史不删除 | `编号\|学号\|电脑\|YYYYMMDD\|时段索引\|状态` |
| `data/error.txt` | 严格读取、校验、保存；保留已处理历史 | `编号\|学号\|电脑\|YYYYMMDD\|故障说明\|处理状态` |
| `data/count.txt` | 缺失建空文件，已有内容只读保留 | P4 每日统计导出，题目指定名称 |

电脑文件必须恰有 40 条、每个编号恰出现一次，状态只能为 0 或 1。示例：

```text
1|0
2|0
3|1
```

以上仅示意前三条，完整文件还须包含 4～40。电脑字段可有首尾空白，不允许空行、额外字段、额外记录、嵌入 NUL、UTF-8 BOM 或超长行。**电脑文件非空但不完整或损坏时直接报错退出，绝不以默认数据覆盖。** 启动引导保留 P0 的文件创建/可读性检查，账户与预约各自按业务访问时严格解析；因此未使用的账户/预约内容损坏不阻止公共基础电脑视图，但相关业务必须报存储错误，不能假装不存在/暂无记录。报告在上报、报告查询和处理时严格解析；统计文件尚不解析，内容保持不变。存在未完成维护时必须先恢复，不能先补建缺失文件掩盖故障。

`storage_save_computers`、`storage_save_accounts`、`storage_save_reservations`、`storage_save_reports` 共用同一套存储快照操作。保存前校验完整集合，独占新建目标旁的 `.tmp` 文件，写完全部记录并检查 `fflush`/`fclose`，然后执行同目录替换。Windows 下使用 CRT `_O_EXCL` 创建临时文件、`MoveFileExA` 替换；其他平台使用 C11 `fopen("wbx")` 和 `rename`。平台差异均有条件编译；Windows 对共享/锁冲突及访问拒绝最多尝试5次（合计等待100毫秒），持续失败仍保留临时文件并报错。电脑文件格式未改变，主菜单没有故障修改操作。

账户注册遵循“验证字段 → 重新读取该角色完整文件 → 查重和容量检查 → 局部快照追加候选 → 完整持久化 → 返回成功”。没有长期账户缓存，保存失败后候选会被丢弃，无法登录该失败注册的账户。注册成功不自动登录。正常登录/退出不重写文件；已有账户的信息和累计时长在追加新账户时保留，输出统一规范为 LF 和十进制整数。

保存失败不先删除旧文件，可能保留 `.tmp`；它也可能包含教学明文凭据，应按账户数据保护。遇到遗留 `.tmp` 时拒绝覆盖它，请先检查、备份，再由使用者手动处理该明确文件。程序不自动批量清理文件。此实现用于单进程课程设计，不提供并发写入协调或断电耐久保证。P3 维护另有下述可重入日志恢复，不能把独立快照保存称作跨文件原子事务。

## P1 使用流程与字段约束

1. 主菜单选择 1 管理员或 2 学生。
2. 入口选择 1 注册，依次输入工号/学号、姓名、密码和确认密码；失败可重新选择注册或返回。
3. 入口选择 2 登录，输入对应角色的标识和密码；失败可再次选择登录，选择 3 返回主菜单。
4. 登录后显示当前角色与标识；学生菜单 1～5、管理员菜单 1～4 已开放，学生 6/管理员 5 的 P4 功能统一提示“该功能尚未开放”。管理员用 6、学生用 7 退出登录，回到角色入口。子菜单也接受 0 返回/退出登录；时段选择的 0 则表示 08:00～09:00。
5. 主菜单选择 4（兼容 0）退出系统。

- 标识大小写敏感，1～31 个 ASCII 字符；首字符必须字母或数字，其余允许字母、数字、`_`、`-`。同一角色不能重复，不同角色有独立命名空间，允许相同标识但分别验证各自文件和密码。一个角色的账户不自动成为另一角色账户。
- 姓名和密码都为 1～63 个 UTF-8 字节，包含结尾的数组容量是 64；姓名最多容纳 21 个常见三字节汉字。四字节字符按实际字节数计。拒绝截断、无效 UTF-8、空字段、控制符、BOM、`|` 及首尾 ASCII 空格，允许内部普通空格。
- 学生累计小时数是 `0～INT_MAX` 十进制整数；新注册强制 0，P1/P2/P3 不修改已有时长或计算统计。
- 账户文件支持 UTF-8 无 BOM、LF/CRLF 和末行无换行。每条记录字段数固定，空行、重复标识、超容量（管理员 30/学生 1000）及非法字段均报错，不跳过坏行继续认证。
- `AuthResult` 明确区分成功、字段无效、重复、未找到、密码错误、存储错误、容量和分配错误。**成功值是 `AUTH_OK == 0`，调用方必须显式比较**，不能沿用旧占位声明中的布尔约定。
- `AuthSession` 只保存 `role`、`user_id`、`logged_in`，由 UI 局部持有，不含密码；登录失败先清空旧会话。`auth_session_has_role` 用于进入角色功能前的权限检查。

## P2 预约规则与流程

日期输入为八位 `YYYYMMDD`，支持 1000～9999 年真实公历日期及闰年。每天开放 08:00～17:00，时段索引 0～8 分别对应 08:00～09:00 至 16:00～17:00。

**新预约仅限本地系统日期的今天至第六天（共 7 个自然日），且开始时刻必须严格晚于当前时刻。** 例如 10:15 时不能预约 10:00～11:00，可以预约 11:00～12:00；11:00 整已不能预约 11:00 开始的时段。自然日差用公历日序号计算，支持跨月、跨年和闰日，不用 `YYYYMMDD` 直接相减。

- 学生菜单 1：输入日期和时段，重新读取电脑及预约文件显示 5×8 视图。查看视图不受创建窗口限制，可查历史；其他学生身份不会暴露。
- 学生菜单 2：输入日期/时段，查看实时视图，输入电脑号，完整预检后展示学号、日期、时间、电脑供确认。选择 1 才创建，0 放弃。确认后再次读取文件、验证学生/故障/冲突/时间，并在写入边界复查时间；保存成功才显示正式编号与详情。
- 学生菜单 3：默认显示本人所有 `BOOKING_ACTIVE` 记录，**包括已过去但未取消的历史记录**；输入 1 查看本人全部历史与已取消记录，0 返回。结果按日期、时段、编号排序，查询不重写文件。损坏文件报告错误，不显示成“暂无预约”。
- 学生菜单 4：只列出本人有效且尚未开始的可取消记录，再输入编号并确认。只能取消本人、仍有效、未开始的预约；已经开始/结束或重复取消均拒绝。旧数据中超出当前七日创建窗口但尚未开始的预约也可取消。取消仅把状态改为 0，不删除记录；保存成功后释放对应座位。
- 未登录、管理员会话、学生账户不存在/损坏、故障电脑、同座位同日期时段占用、同学生同日期时段多座位均在业务层拒绝，不能靠直接调用绕过 UI 校验。学号来自 `session->user_id`，不能由预约输入替换。
- 不同日期或不同时间段可以预约同一台电脑；取消记录不参与占位和冲突。故障电脑优先显示 `!`。视图下方数量是 `*`/`#`/`!` 的座位数量，总和 40；不作为实际上机人数或 P4 统计。

预约文件每行六字段：`正整数编号|学号|电脑编号|八位日期|时段索引|状态`。编号范围 1～INT_MAX、电脑 1～40、索引 0～8、状态有效 1/取消 0。字段不允许分隔符注入、空值、数字首尾空白、符号、溢出、NUL、BOM、多字段/少字段或超长行；支持 LF/CRLF 和末行无换行。

完整加载/保存前都会校验字段、全部编号唯一，以及活跃预约的 `日期+时段+电脑` 和 `学号+日期+时段` 唯一。空文件是合法空表，**业务执行中缺失/损坏的文件绝不当作空表初始化**。记录最多 100000 条，包含取消和历史；新编号取全部记录（含取消）的最大值加一，原始记录乱序也正确，达到 INT_MAX 后拒绝新建，不回绕复用。历史记录即使日期已过也不删除；只验证历史学号格式，不因该学生后来不在账户表而擦除历史事实。当前操作者的账户存在性仍严格验证。

预约数组使用 `ReservationList` 动态堆内存，从 64 条起按需扩容至上限，不把十万条放在栈上。`realloc` 使用临时指针并检查容量/字节乘法溢出；失败保持原集合。完整冲突校验排序堆上的指针索引，避免两两比较，不改变原文件或记录顺序。加载失败不发布部分结果，调用方用 `storage_free_reservations` 释放；拥有数组的集合不可浅复制后分别释放。

时间通过 `BookingContext` 显式注入，NULL 时使用标准 C `time/localtime` 读取本地时间。正式入口没有读取测试环境变量、固定日期或硬编码“今天”；固定/推进时钟及内存、I/O 失败控制仅在 `tests/` 的独立测试程序内。P2 不修改 `Student.time`，预约事实留给 P4 后续计算，不把提前预约算成已实验时长。

## P3 故障与管理员流程

学生菜单 5：输入电脑编号，显示当前状态和本人在该机的历史报告，再输入故障说明并确认。故障电脑仍能看历史，但不再创建新报告；正常电脑的上报不会自动变为故障，也不会取消预约。同一学生同一电脑只能有一条待处理报告。学号只能从已认证会话取得，业务层复查实际学生账户。

报告使用 UTF-8 无 BOM，每行 `正整数编号|学号|电脑|YYYYMMDD|说明|状态`；状态待处理 0/已处理 1。支持 LF/CRLF 和末行无换行。说明 1～255 字节（最多 85 个常见汉字），拒绝无效 UTF-8、BOM、NUL、控制符、分隔符和首尾 ASCII 空格；不截断注册或报告输入。编号取全部历史最大值加一，达到 INT_MAX 拒绝新建。`FaultReportList` 从堆上按需扩容，最多 10000 条；全量校验编号唯一和待处理学生/电脑组合唯一，使用排序索引，不创建大型栈数组。加载失败不修改输出，保存前验证全部记录。

管理员菜单 2 的二级菜单：1 全部电脑状态，2 标记故障，3 恢复正常，4 报告列表，5 处理报告，0 返回。报告列表默认待处理，可选已处理、指定电脑和全部。标记故障先完整校验电脑/预约，展示受影响预约编号、日期、时段、学号，确认后重新校验并保存。只取消**确认时刻严格未开始**的有效预约，已开始、已结束和已取消记录均保留。重复标记/恢复提示无需操作；恢复不复活取消记录。报告处理三种动作：确认故障、已维修恢复、未发现故障仅关闭；报告状态独立于电脑状态，关联更新完成后才关闭报告。

管理员菜单 3：选择日期/时段，查看有效预约人数、空闲/故障电脑、座位图和真实预约学生学号/姓名/电脑。人数不是签到或实际使用人数；故障符号优先，过去未取消预约仍可能与当前故障状态重叠。菜单 4：精确输入学号，显示姓名、有效预约数、全部历史数（含有效及取消）与预约明细，可切换全部历史。专属 `admin_query_usage` / `admin_query_student` 直接检查管理员权限，未借用学生身份；结果不含密码或累计实验时间。相关文件读取失败明确报错，不能显示成零预约。

### 维护日志与恢复范围

每次仅允许一个维护操作，操作意图文件为 `data/maintenance.txt`，一行：

```text
P3|1|动作|电脑编号|关联报告编号|YYYYMMDD|小时|分钟|秒
```

动作 1 标故障并取消未来预约、2 恢复正常、3 仅关闭报告；报告编号 0 表示独立电脑维护，动作 3 必须关联报告。先完整预检相关数据及临时路径，再独占写 `maintenance.txt.tmp` 并替换发布意图。随后依次保存电脑、预约、最后保存关联报告；全部达到目标后将意图移动到 `maintenance.done.txt`（覆盖上一条已完成意图供诊断），不存在意图时不额外创建日志文件。

确认时刻保存在日志中。重启使用该固定时刻重放，不会因为预约已在停机期间开始就遗漏取消；重复执行只补齐未完成变更。启动恢复早于数据补建，缺失/损坏的来源不能被初始化成空表。恢复时分别将该已发布操作的残留临时快照移动到 `computers.recovery.txt`、`reservations.recovery.txt`、`error.recovery.txt`，保留草稿后重新生成；不批量删除文件。这些诊断备份可被下一次恢复覆盖。

意图发布后任何保存/完成归档失败返回“维护未完成”，保留日志并阻止全部公开保存及依赖一致视图的业务查询/写入；需重启或显式调用 `storage_recover_maintenance()`。若源文件、日志或临时路径无法恢复，启动失败，保留证据；人工修复明确的故障路径后再重启，不得随意删除未完成意图。意图发布前已有的临时文件不归本操作所有，拒绝覆盖，由使用者检查处理。

保证正常成功时相关文件一致、普通写入失败不报成功、两个保存之间进程退出后可重放完成、重复恢复幂等。**这不是数据库的跨文件原子提交，也不承诺物理断电/磁盘控制器层耐久性。** 限单进程、无外部并发修改；数据和日志必须一起备份，不支持脱离日志任意恢复单个文件。正式代码没有测试专用环境变量或中断后门。

## 教学安全限制

按原题结构使用明文密码文本文件，**这不是安全的生产账户方案**。不要输入真实或复用密码。当前不实现密码哈希、加密、锁定/限速或管理员注册审批；任何使用控制台的人都可注册管理员，这是课程要求下的演示行为。

Windows 实际控制台输入密码时临时关闭回显，所有正常返回/EOF/输入错误路径尝试恢复；重定向输入不会打印密码。非 Windows 平台使用标准输入，未实现终端密码隐藏。程序的错误提示仅包含错误类别、路径和行号，不打印账户记录或凭据。临时密码缓冲区会擦除，但不声称能抵抗内存取证、终端外部记录或本机文件篡改。测试使用合成凭据，只把账户内容存于隔离数据文件，不写调试日志或测试报告。
