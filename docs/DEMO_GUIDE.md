# LabSlot 课程设计演示指南

正式程序是纯 C11 + Win32。演示使用真实系统时钟、真实业务 API 和独立 data；没有演示模式、固定账户或固定时钟。展示的是预约事实，不能称为签到或实际上机时长。

## 编译和隔离目录

在仓库根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
# 答辩前完整检查
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Analyze -Test -GuiTest
```

需要 MinGW-w64 GCC/windres；脚本支持本机便携工具链和 `-Compiler`。构建保留 `smart-lab.exe`、`LabSlot-GUI.exe`，不把程序或 data 提交到 Git。程序运行不需要 Python，准备脚本和测试需要 Python。

选择一个**尚不存在**的目录，父目录须已存在。例如在 PowerShell 中先生成本次路径，再执行准备脚本：

```powershell
$demoPath = Join-Path $env:USERPROFILE ('Desktop\LabSlot-Demo-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
python scripts/prepare_demo.py --target $demoPath
# 脚本显示完整路径后，输入该路径确认，才会创建目录和复制程序。
& (Join-Path $demoPath 'LabSlot-GUI.exe')
```

自动化复现可显式使用 `--confirm-new-directory` 确认该 `--target`。脚本拒绝已存在目录、相对目录、链接/重解析点、项目真实 data 及其子目录，不覆盖任何文件，不复制账户/业务数据，不删除文件。首次启动由正式 GUI 在 EXE 旁初始化空 data；这与从别处启动控制台的当前工作目录规则不同。

不要同时启动项目 GUI 与演示 GUI，正式 GUI 采用单实例保护。不要让控制台、GUI 或外部编辑器同时写相同 data。演示目录中的 `DEMO_SESSION.md` 记录准备当天和建议日期；隔天演示须重新核对。

## 账户和日期

通过 GUI 注册合成学生与管理员，例如学号 `DEMO-STU1`、姓名“演示学生甲”，工号 `DEMO-ADM1`、姓名“演示管理员”。选择只用于演示的密码，不用真实学号、姓名或复用密码，也不要把密码放进截图、日志或报告。

学生预约窗口是**今天到第六天**，且所选时段必须尚未开始。推荐所有主要流程选“明天 08:00–09:00”，第二条预约选“明天 09:00–10:00”；不要硬编码日期。当天较晚时不要用已经开始的时段。周报选择预约当天，让程序自动定位完整周一至周日。

新账户完成预约小时为 0 是正确结果。提前预约、取消预约和故障取消不计完成小时；要现场展示非零完成小时，需要先保留一条正常有效预约并等待其实际结束。不要改系统时钟或写假缓存来制造完成小时。

## 学生演示（约 5 分钟）

1. 打开隔离目录的正式 GUI，展示登录页，进入注册，填写合成学生资料后登录。
2. 查看工作台，再进入座位预约；解释 5×8 排列、讲台方向及空闲/预约/故障/选中文字。
3. 选择明天 08:00–09:00，选择正常空闲电脑 A，核对确认框后预约。
4. 在“我的预约”查看编号、日期、电脑；切换有效/历史，查看详情。
5. 返回相同时段选择另一台空闲电脑，再确认预约，展示同一学生同一时段冲突被拒绝。已预约电脑不能再次选中是另一个前端状态。
6. 回到“我的预约”，选择 A，先在取消确认框选择否，证明记录保留；再次确认取消，核对列表及座位空闲状态。
7. 为管理员故障联动演示，在正常电脑 B 上保留**两条未开始预约**：明天 08:00–09:00 与 09:00–10:00。不要取消这两条。
8. 在故障报告页选 B，输入中文与英文混合描述，例如“显示器偶发闪烁，Display A 连接线待检查”，确认提交；查看本人待处理状态。
9. 查看个人统计，解释预约数、取消数和完成小时的真实含义；退出登录。

## 管理员演示（约 5 分钟）

1. 注册或登录合成管理员，展示管理工作台的设备及待处理报告数量。
2. 使用情况选明天 08:00–09:00，核对学生、电脑与预约编号；说明人数不代表签到。
3. 学生查询输入完整学号 `DEMO-STU1`，切换有效/全部历史，展示成功与不存在学号的清空状态。
4. 在故障报告中选 B 的待处理报告，查看详情，选择“确认故障”，展示受影响的两条未来预约列表，先选择否返回。
5. 再次预览并明确确认，核对 B 变为故障、报告已处理；在学生查询历史中确认两条未来预约已取消。业务层会在最终提交时重新校验。
6. 在电脑维护中选择 B，确认恢复正常；再次检查历史，已取消预约不会复活。
7. 日报选择预约日期，展示九时段柱图、人数去重、容量 360；周报展示七天、整周去重和容量 2520。取消后统计相应减少到零也是正确结果。
8. 如需展示非零统计，先退出管理员，学生在正常电脑 C 上新增明天某时段预约，再切回管理员刷新。这样每一个数字都来自实际 GUI 操作。
9. 在每日模式确认日期和导出概要后导出 count.txt，核对成功提示。解释它是当时快照；后续预约变化须重新导出。
10. 退出登录，关闭窗口。演示结束保留完整 data 和维护日志，避免只备份单个文件。

## 截图和恢复初始环境

建议使用同一逻辑客户区 1280×800，统一系统缩放，输入资料均为合成信息。截图存放本地 `docs/screenshots/`，默认不提交 Git；密码保持掩码，截图前关闭输入法候选框和无关窗口。最终验收记录区分真实系统缩放、消息模拟布局和未验证场景。

重新开始时，关闭演示 GUI，再运行准备脚本创建**另一个全新目录**。原目录保留供复查，不批量删除，也不在真实 data 上重置。不明 `.tmp` 或未完成维护日志必须先完整备份并按 P3 恢复流程处理；不能删除日志来绕过门禁。

## 演示前检查单

- 双目标严格编译、全部回归和 GCC 静态分析通过。
- 演示目录与项目真实 data 分离，系统时间正确，预约日期仍在有效窗口。
- 键盘 Tab/Enter、中文输入与错误恢复已在本机实际检查。
- 系统缩放若临时调整，记录原值并在结束后恢复；无法验证的缩放、多显示器或输入法场景如实标注。
- 演示中发现未完成维护或保存失败时停下说明真实错误，保留文件；不要把失败说成成功。

## P6 四项创新串联演示（建议另建全新目录）

继续使用上面的准备脚本创建**新的隔离目录**，不要重置旧目录或项目data。正式程序使用真实本地时钟。为便于核对数字，以下示例以新目录、正常40台、没有其他记录、一条新报告为前提；已有数据必须按真实结果讲解，不强凑示例值。

1. 注册并登录合成学生，进入“座位预约→智能推荐”。选**明天08:00开始、2小时**，比较三种偏好的公开权重，查看前三项分数和原因。新目录中前三项可能同为100分，改变偏好也可能保持相同排序；不要声称所有数据下排序必然变化。权重取舍的精确对照用P6.1验收示例说明。
2. 点击一个推荐结果，座位图应高亮同一电脑并带入2小时，蓝色范围为08:00–10:00。点击“连续预约”，先在完整摘要选择否，说明未创建；再次确认后记录全部新编号。新目录中是1、2两条一小时记录，个人预约列表显示2条，完成小时仍为0。
3. 点击“本周预约热度”，日期改为**预约当天**，定位它所在完整周。若明天是下周一，不要仍停在今天所在周。两个时段各有1条时，数量1/40、利用率2.50%；点击单元格查看精确值，再用“查询该时段座位”返回合法未来时段。过去/已开始/超七日窗口的格不能绕过P2时间规则。
4. 在学生“故障报告”选择刚预约的电脑，提交一条合成线索。上报只创建待处理报告，电脑仍正常、两条预约仍有效。退出学生。
5. 注册/登录合成管理员，在工作台点击“设备健康分析”。此时该电脑若只有这一条今天的待处理报告，评分为100−8−4=**88**，真实状态仍正常，未处理报告1条。解释：这是公开规则下的维护辅助等级，不是硬件检测或未来故障概率。无记录正常设备显示“暂无故障记录”。
6. 选择该电脑，查看构成，再点“查看相关故障报告”。页面应自动筛选到同一电脑。选中报告“确认故障”，查看包含两条未来预约的影响预览，默认否；确认后电脑变为故障、报告已处理，两条未来预约均取消。评分为100−65−8=**27**，界面明确“故障（已知）”，表示已经确认的事实。
7. 管理员统计中心打开热力图，选择预约当天，确认这两个时段已不计取消记录。40仍是固定理论容量，不因当前故障改写历史分母。
8. 在“电脑维护”恢复该电脑正常。回健康页，只有这条已处理近期报告时为**92**，报告记录保留；已取消的两条预约不复活。查看学生历史或切回学生核对。
9. 退出并关闭窗口，保留该目录全部data及维护完成日志。不要删除报告、临时快照或只备份部分文件以制造演示结果。

可将“推荐→原子预约→热力统计→报障→维护评分”作为一条答辩主线。推荐刷新、热图与健康分析是只读；真正的预约、报障及维护仍经过确认和原业务保存。连续预约失败没有部分成功，成功后页面刷新失败会单独说明已保存及正式编号。
